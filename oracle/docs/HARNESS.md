# DOS ground-truth harness (`oracle/harness/dosrun.sh`)

Boots Keen 4 or Keen 5 in the pinned DOSBox-X under a private Xvfb, optionally drives it with
keys, and captures screenshots and/or an AVI. It is the oracle runner for tracker #27; Keen 6 is
not supported yet. Game data is read from `$KEEN_DATA` (default `~/keen-data-decomp`), copied
into a throwaway work dir (with CONFIG/SAVEGAM removed for a clean start) and deleted afterwards.
Nothing in the data dir is modified, and nothing from it is committed.

## Usage

    oracle/harness/dosrun.sh <4|5> [--exe path] [--args "..."] [--keys script] [--avi out.avi]
                            [--shots dir] [--timeout s] [--wait s] [--keep]

| option | meaning |
|---|---|
| `--exe` | EXE to run instead of the original, e.g. a rebuilt one: `~/keen-build/k4/OUT.EXE` (left by `oracle/tools/verify-dos.sh`; `make verify-k4`). It is copied in under its own name. |
| `--args` | Game command line, default `/TEDLEVEL 1`. Others: `/NOWAIT`, `/TEDLEVEL n`, `/DEMO`-style params. |
| `--keys` | Key script (below). |
| `--avi` | Record DOSBox-X's own AVI (one entry per emulated frame, no screen-grab tearing) for the whole run. |
| `--shots` | Screenshot dir (default `./dosrun-shots`). `boot.png` is taken after `--wait` seconds (default 12). |
| `--timeout` | Hard cap on the whole run in seconds (default 60). |
| `--keep` | Keep the work dir (conf, `dosbox.log`, `stdout.log`) for debugging. |

Exit status: 0 ok, 1 usage/setup error, 2 emulator died early or no screenshot, 3 timeout.
Prints `SKIP` and exits 0 if the game data is absent.

Examples:

    oracle/harness/dosrun.sh 4 --shots out/k4                              # original Keen 4, level 1
    oracle/harness/dosrun.sh 5 --exe ~/keen-build/k5/OUT.EXE --args "/TEDLEVEL 2" --shots out/k5-rebuilt
    oracle/harness/dosrun.sh 4 --keys moves.txt --avi out/k4.avi --shots out/k4

### Key script

One command per line, `#` comments. Keys are sent with xdotool to the Xvfb display, after the
`boot.png` screenshot.

    sleep 1.5      # seconds
    key alt        # xdotool key name (Return, space, ctrl+x ...)
    down Right     # hold ...
    up Right       # ... release
    type text      # xdotool type
    shot name      # screenshot -> <shots>/name.png

Driving menus this way is flaky; prefer `/TEDLEVEL`, `/NOWAIT` and file-based assertions. In
`/TEDLEVEL` mode F9 quits the game, so do not bind capture to it (the AVI uses Scroll Lock).

## Emulator

DOSBox-X 2026.08.02, the build pinned by the keen456 repo, found at
`~/git/keen456/native/vendor/dosbox-x-2026.08.02/dosbox-x` (its `lib/` is added to
`LD_LIBRARY_PATH`). Override with `DOSBOX_X=/path/to/dosbox-x`. Config: `machine=svga_s3`,
`core=normal`, `cycles=fixed 25000`, sound off, `output=surface`. The game is PIT-timed (70 Hz
tics), so cycles do not change game speed. The runner never rebuilds DOSBox-X.

## Dependencies

- bash, coreutils (`mktemp`, `timeout`, `nice`, `ionice`)
- `xvfb-run` + `Xvfb`, `xdotool`, ImageMagick `import` (screenshots)
- the pinned `dosbox-x` binary and its shared libraries (copy the `dosbox-x-2026.08.02/` dir to
  the droplet and point `DOSBOX_X` at it)
- game data under `$KEEN_DATA/keen4` and `keen5`
- no real display; no ffmpeg needed (only to inspect the AVI afterwards)

Each run takes about 15 s and one emulator; runs are `nice -n 19 ionice -c3`. For parallel runs
on a droplet, run several invocations (each has its own work dir and Xvfb via `xvfb-run -a`).

## Known limitations

- Screenshots use `import -window root` on a 1024x768 Xvfb screen: the 320x200 game is scaled
  and centred (not the raw framebuffer). For pixel-exact frames use `--avi` (raw emulated frames).
- Timing of key scripts is wall-clock, so not frame-exact; deterministic input needs demo mode
  or a future in-emulator recorder.
- A rebuilt EXE is currently byte-identical to the original, so it only proves the rebuild
  boots. The same flag will run non-identical builds later.

## Traces

`oracle/tools/keendump.sh run <4|5> <demo> <out.trc>` plays one built-in demo with the KEENDUMP build
(headless DOSBox via `oracle/tools/dosbuild.sh`; exits when the demo ends) and writes the per-frame trace.
Running it under this harness's DOSBox-X instead is described in [`TRACE_FORMAT.md`](TRACE_FORMAT.md).

## Motion trace (#82)

`tools/motiontrace.py` turns a trace into per-frame screen-space motion and an unevenness score.
Python 3 stdlib only; plots are optional (`.svg` is generated by the tool itself, `.png` needs matplotlib).

    tools/motiontrace.py -e 4 k4-d0.trc [--slot N | --class slugobj] [--csv out.csv] [--plot out.svg]
    tools/motiontrace.py -e 4 --compare dos.trc fork.trc     # scores side by side
    tools/motiontrace.py positions.csv                       # CSV input: frame,x,y (screen px)
    tools/motiontrace.py --range 140 255 ...                 # score only frames 140 <= f < 255

The default object is Keen (slot 0); `--slot` / `--class` (name from the `classtype` enum, first live
object of that class) pick another. The CSV has one row per frame: `cam_x, cam_y` (px), `obj_x, obj_y`
(world px), `scr_x, scr_y` (screen px = object minus camera) and the per-frame deltas `dcam_*`, `dscr_*`.
A CSV with `frame,x,y` (or `frame,scr_x,scr_y`) is also accepted as input, so the engine's
present-timestamp log (#74/#30) can be scored with the same code (one row per presented frame; an extra
timestamp column is ignored).

**Camera.** The trace format has no scroll origin (docs/ACTORS.md §7), so the camera is re-derived by
running the game's own code on Keen's recorded state: `CenterActor` for the start (Keen's position before
frame 0, `x - xmove`), then `ScrollScreen` (or `WorldScrollScreen` on the world map) once per frame with
`tics = 3`, bounded like `RF_Scroll`. A frame where Keen moves more than `xmove`/`ymove` explain (a
teleporter) re-centres the camera, and steps into that frame are excluded from the scores. Not modelled:
level scroll blocks, K6 ground slam; map-edge clamps only apply with `--map-size W H` (tiles), otherwise
only the top/left edge is clamped. Use short, central stretches (`--range`) where this matters.

**Display grid.** Vanilla draws on a 2-pixel grid (EGA pan mask, 4 sprite pre-shifts; #89), so camera and
object pixel positions are floored to `--grid 2` (default) before subtracting; `--grid 1` is raw.

**Scores** (per series `cam_x cam_y scr_x scr_y`, steps = change per frame in px): `step_std` (population
stddev, the #89 `stats.py` metric), `mean_abs`, `max_step`, `frozen_pct` (share of zero steps), `alt`
(reversing step pairs with both |step| <= 1, i.e. +1/-1 jitter), `uneven` (consecutive same-direction
steps of different size, e.g. 2,4,2,4). Perfectly even motion scores 0 on `step_std`, `alt` and `uneven`.
Test: `python3 tools/test_motiontrace.py` (synthetic traces and CSVs only).

**Baseline, Keen 4 golden demos, Keen on screen (`scr_x`/`scr_y`), per sim frame (35 Hz), grid 2:**

| demo | frames scored | scr_x step_std | scr_x uneven | scr_y step_std | cam_x step_std | cam_x uneven |
|---|---:|---:|---:|---:|---:|---:|
| k4-d0 | 807 | 1.224 | 36 | 4.605 | 2.402 | 188 |
| k4-d1 | 647 | 1.419 | 34 | 4.509 | 2.232 | 90 |
| k4-d2 | 747 | 1.394 | 32 | 3.861 | 2.502 | 119 |
| k4-d3 | 642 | 1.762 | 51 | 4.183 | 3.489 | 177 |
| k4-d4 | 264 | 2.621 | 44 | 4.046 | 2.052 | 36 |

`alt` is 0 everywhere: vanilla never reverses by one pixel; its unevenness is step *size* (2,4,2,4 on the
camera, where Keen's screen x stays in the scroll window and mostly does not move). `scr_y` is large
because Keen's jumps and falls move him on screen. These are the numbers a fork build must not make worse
(sim-frame level); display-rate numbers come from the present log.
